----------------------------------------------------
ANDROID: FRAMEWORKS & SECURITY LIBRARIES
----------------------------------------------------

- Flutter (Dart SDK)
    Cross-platform UI framework. The Dart URI parser had a
    critical auth bypass (CVE-2022-3095) where backslashes
    were misparsed. The pub client also had a path traversal
    issue (CVE-2026-27704). Specific Flutter plugins
    (file_selector_android, image_picker_android) had file
    name sanitization flaws (CVE-2024-54461/54462).
    Ref: https://vuldb.com/cve/CVE-2022-3095 [citation:8]
    Ref: https://security-tracker.debian.org/tracker/CVE-2026-27704 [citation:3]
    Ref: https://app.opencve.io/cve/?vendor=flutter [citation:4]

- PairIP (Google pairipcore / libpairipcore.so)
    Commercial-grade app protection injected into APKs.
    Validates Play Store installation, app signature, and
    blocks Frida/GDB. It uses an obfuscated VM to hide
    logic. Public bypasses exist (LSPosed module pairipfix,
    Frida scripts to hook libpairipcore.so, and guides to
    strip the VM entirely).
    Ref: https://modules.lsposed.org/module/io.github.ahmedmani.pairipfix/ [citation:1]
    Ref: https://github.com/notmadcode/gPairIp-Bypass [citation:5]
    Ref: https://medium.com/@farimarwat/bypassing-pairip-vm-protection-on-android-a684c1559b39 [citation:11]

- Third-Party Logging Libraries (Timber, SLF4J, Firebase)
    Used for debugging/analytics. A large-scale study found
    that nearly half of apps using third-party logging had
    privacy leaks. These libraries may buffer data locally or
    transmit logs to remote servers, leaking sensitive user
    data. Timber concentrates heavily on DEBUG levels, while
    Firebase is dominated by Analytics Events.
    Ref: https://www.computer.org/csdl/proceedings-article/saner/2026/858200a468/2hNeGHStqZW [citation:6]
    Ref: https://dspacemainprd01.lib.uwaterloo.ca/server/api/core/bitstreams/dd05e5b3-d299-4e95-973f-0ba688661e50/content [citation:12]


----------------------------------------------------
iOS: COMMON LIBRARIES (SECURITY CONTEXT)
----------------------------------------------------

- Alamofire (Networking)
    Swift HTTP networking library. It is not inherently
    vulnerable, but developers can disable certificate
    validation or use insecure custom trust policies, which
    enables Man-in-the-Middle attacks. Proper use of
    ServerTrustPolicy with pinning is required for security.
    Ref: https://db.fluidattacks.com/fix/swift/147/ [citation:24]
    Ref: https://git.iko.soy/Alamofire/Alamofire/commit/6e8231492a2ed98bfb75b97328795124b9f4754f [citation:29]

- SDWebImage (Image Loading)
    Image loading/caching library. It relies on underlying
    codecs (libjpeg, libpng, WebP). Vulnerabilities in those
    codecs can be exposed through SDWebImage, potentially
    leading to RCE or DoS via malicious images or "pixel
    bomb" resource exhaustion. Keeping dependencies updated
    is critical.
    Ref: https://github.com/xvnpw/sec-docs/blob/main/objectivec/sdwebimage/sdwebimage/2025-02-14-gemini-2.0-pro-exp/attack-surface.md [citation:30]

- CocoaLumberjack (Logging)
    Logging framework. Risks include sensitive data exposure
    through log files (local or remote) and path traversal if
    log file paths are constructed from unsanitized input.
    Misconfiguration (verbose logging in production) is a
    common issue.
    Ref: https://raw.githubusercontent.com/xvnpw/sec-docs/refs/heads/main/objectivec/cocoalumberjack/cocoalumberjack/2025-02-13-gemini-2.0-pro-exp/threat-modeling.md [citation:21]
    Ref: https://raw.githubusercontent.com/xvnpw/sec-docs/refs/heads/main/objectivec/cocoalumberjack/cocoalumberjack/2025-01-31-gemini-2.0-flash-thinking-exp/attack-surface.md [citation:27]

- Realm / Core Data (Database)
    Local databases. Security risk depends on developer
    configuration. If sensitive data is stored unencrypted,
    it can be extracted from the device filesystem (especially
    on jailbroken devices or via backups).
    (Note: No specific CVE found in the search results for
    these libraries; risk is configuration-based.)


----------------------------------------------------
UTILITIES (FROM PREVIOUS DISCUSSION)
----------------------------------------------------

- otool
    macOS command-line tool for inspecting Mach-O binaries
    (headers, linked libraries). Ships with Xcode CLI tools.

- balenaEtcher
    OS image flasher (SD/USB). Used to flash NetHunter or
    custom ROMs. NOT a pentesting tool. Only download from
    official sources (balena.io/etcher).
    Ref: https://etcher.pages.dev/ [citation:17]
    Ref: https://blog.balena.io/beware-false-software-claiming-to-be-balenaetcher/ [citation:23]

- Baleno
    Network management GUI (Serial, SSH, TFTP, IP Scanner,
    SNMP, VulnScan). Unrelated to mobile app pentesting.
    Ref: https://aur.archlinux.org/packages/baleno-git [citation:16]


----------------------------------------------------
SUMMARY: EXPLOITABILITY NOTES
----------------------------------------------------
- PairIP: Exploitable in practice. Multiple public bypasses
  exist, though it raises the bar for casual modding.
- Flutter/Dart: Core SDK had critical CVEs. Plugin ecosystem
  also had vulnerabilities. Keep SDK and plugins updated.
- Logging (Android/iOS): High privacy risk. Not always a
  "code execution" exploit, but significant data leakage.
- Networking (Alamofire): Risk is configuration-dependent.
  Insecure trust policies are the main issue.
- Image Loading (SDWebImage): Risk via underlying codecs.
  Keep dependencies patched.
